## 🔎 What Does It Do?

**ai-session-search** is a **local-first, read-only full-text search engine** for your AI coding sessions. It indexes all your past conversations with various AI tools and lets you find any message, code snippet, or discussion instantly.

### Supported AI Tools:
- Claude Code
- Codex CLI
- Cursor
- OpenCode
- Copilot CLI
- Kimi Code
- And more

## 💡 Features

- **Full-Text Search**: Search across all your AI conversations using keywords, phrases, or code snippets.
- **Local-First**: All data stays on your computer. No cloud uploads, no privacy concerns.
- **Read-Only**: Your conversations are never modified. Safe to use with any AI tool.
- **Fast SQLite Backend**: Uses SQLite for lightning-fast searches even with thousands of sessions.
- **Organized Results**: View search results sorted by relevance, date, or AI tool.
- **Cross-Platform**: Works on Windows, macOS, and Linux.

## 🖥️ System Requirements

- **Operating System**: Windows 10 or later, macOS 10.15+, or Linux (Ubuntu 20.04+)
- **Storage**: 50 MB for the application, plus space for your session database
- **Memory**: 256 MB RAM minimum (512 MB recommended)
- **Internet**: Required only for initial download

## 📖 How to Use

### Step 1: Launch the Application
Open **ai-session-search** from your applications folder or Start menu.

### Step 2: Import Your Sessions
Click "Import Sessions" and select the folder where your AI tools store conversation logs. The app will scan and index all supported formats.

### Step 3: Search
Type any word, phrase, or code snippet into the search bar. Results appear instantly as you type.

### Step 4: View Results
Click any result to see the full conversation context. Use the filter options to narrow down by AI tool or date range.

## 🛠️ Troubleshooting

### Common Issues:

**"No sessions found"**
- Ensure your AI tool's conversation folder is correctly selected.
- Check that your AI tool is saving session logs locally.

**"Application won't start"**
- Make sure your system meets the minimum requirements.
- Try running as administrator (Windows) or with proper permissions (Mac/Linux).

**"Search is slow"**
- For large databases, the first search may take longer. Subsequent searches will be faster.
